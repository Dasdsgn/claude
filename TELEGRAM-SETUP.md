# Как подключить бриф к Telegram-боту

Итог: клиент нажимает «Отправить бриф» → через минуту в вашем боте приходит структурное сообщение + файлы, которые он приложил. Всё бесплатно.

**Схема:** сайт (GitHub Pages) → маленький «почтальон» (Cloudflare Worker) → ваш бот в Telegram.
Почтальон нужен, чтобы токен бота не лежал в открытом коде сайта. Иначе любой мог бы его увидеть и слать спам от имени бота.

Нужно 4 шага, около 15 минут.

---

## Шаг 1. Создайте бота

1. В Telegram найдите **@BotFather** (с синей галочкой).
2. Отправьте `/newbot`.
3. Введите **название** (любое, видно в чате), например: `Мини-бриф`.
4. Введите **username**, он должен заканчиваться на `bot`, например: `moy_brief_bot`.
5. BotFather пришлёт **токен**, длинная строка вида `123456789:AAH...`. Скопируйте и никому не показывайте. Не вставляйте его в чаты, GitHub и документы.

## Шаг 2. Узнайте свой chat_id

1. Откройте своего бота (ссылка `t.me/ваш_username_bot`) и нажмите **Start**. Напишите ему любое слово. Без этого он не сможет писать вам.
2. Напишите боту **@userinfobot**, он ответит вашим `Id: 123456789`. Это и есть chat_id.

Если хотите получать заявки в группу (например, с менеджером): добавьте бота в группу, напишите в ней что-нибудь, откройте в браузере
`https://api.telegram.org/bot<ТОКЕН>/getUpdates` и найдите `"chat":{"id":-100…`. Для групп id начинается с минуса.

## Шаг 3. Создайте «почтальона» на Cloudflare

1. Зарегистрируйтесь на **dash.cloudflare.com** (бесплатно, карта не нужна).
2. Слева: **Workers & Pages** → **Create** → **Create Worker** → имя `brief-proxy` → **Deploy**.
3. Нажмите **Edit code**. Удалите всё, что там есть, вставьте целиком содержимое файла [`worker/worker.js`](worker/worker.js) → **Deploy**.
4. Вернитесь на страницу воркера: **Settings** → **Variables and Secrets** → **Add**. Добавьте три переменные:

   | Имя | Тип | Значение |
   |---|---|---|
   | `BOT_TOKEN` | **Secret** | токен из шага 1 |
   | `CHAT_ID` | Text | число из шага 2 |
   | `ALLOWED_ORIGIN` | Text | `https://dasdsgn.github.io` (без `/claude/` и без слэша на конце) |

   Нажмите **Deploy**.
5. Скопируйте адрес воркера. Он выглядит как `https://brief-proxy.ВАШ-ЛОГИН.workers.dev` (на странице воркера вверху).

## Шаг 4. Впишите адрес в сайт

В файле `brief.html` найдите блок `CONFIG` в начале скрипта и вставьте адрес:

```js
ENDPOINT: "https://brief-proxy.ВАШ-ЛОГИН.workers.dev",
```

Тут же поменяйте `BRAND` (ваше имя) и `REPLY_TIME`. Сохраните и отправьте на GitHub (`git push`). Страница обновится по адресу
**https://dasdsgn.github.io/claude/brief.html** примерно через минуту.

---

## Проверка

1. Откройте страницу, заполните только имя, контакт и согласие, пройдите до конца, нажмите «Отправить бриф».
2. В боте появится сообщение «🆕 Новый бриф». Если пришло, всё работает.
3. Включите уведомления для бота (профиль бота → Уведомления), чтобы заявки приходили со звуком.

Пока `ENDPOINT` пустой, страница работает в **тестовом режиме**: всё проходит, но ничего не отправляется (данные видны в консоли браузера).

## Если не работает

| Что видите | Причина |
|---|---|
| «Не удалось отправить» на сайте | Проверьте `ALLOWED_ORIGIN`: ровно `https://dasdsgn.github.io`, без пути |
| Бот молчит, на сайте успех | `CHAT_ID` неверный, или вы не нажали Start у бота |
| Ошибка `telegram: Unauthorized` | Неверный `BOT_TOKEN`. Перевыпустите: BotFather → `/token` |
| Файл не приходит | Файл больше 10 МБ или больше 5 штук |
| У части клиентов из РФ не отправляется | Домен `workers.dev` иногда блокируется провайдерами. Решение: привязать к воркеру свой домен (Workers → Settings → Domains & Routes) |

## Безопасность

- Токен хранится только в Cloudflare, в репозитории его нет.
- Если токен случайно «засветился»: BotFather → `/revoke` → выберите бота. Затем обновите секрет в Cloudflare.
- Воркер принимает запросы только с вашего сайта (`ALLOWED_ORIGIN`), в форме есть скрытое поле-ловушка для ботов.
- Перед запуском для клиентов замените шаблон `privacy.html` настоящей политикой (покажите юристу). Сбор персональных данных в РФ регулирует 152-ФЗ.
